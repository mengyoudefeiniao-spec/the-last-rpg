# 20260925 · 世界观基调与轮回机制

> ⚠️ **本记录的部分内容已被取代**：文中「残章」已更名为「**残魂**」，Canon 铁律亦扩充至 10 条。
> 后续变更以 `20260925-残魂收集机制与终局调整.md`、`20260925-残魂双类与自我归一.md` 为准。

## 背景

`docs/` 已按「四条轨道」规划就位，但尚无任何正文。剧本创作的第一个岔口有三：
世界观基调（西幻 or 东方）、产出落点（是否写 `data/`）、以及「轮回转世」这一核心概念到底以哪种方式在剧情里运作。
三者必须先定，否则后续所有文档（人物、地理、主线）会朝不同方向长。

值得一提的是：实现轨道 `src/data/types.ts` 中已出现 **`talisman`（符箓）/ `spiritTreasure`（灵宝）/ `summon`（召唤）/ `capture`（捕捉）** 等术语，
明显是**东方修仙**语义，而立项时口头描述用的是「魔法与武技」（偏西幻）。两者存在冲突，需要显式收敛。

## 备选项

### A. 世界观基调
1. 西幻魔法为主，把仙侠术语收编为体系内分支（如法宝→魔器）。
2. **东西方双体系并存**。
3. **纯东方仙侠，放弃「魔法与武技」的说法。**

### B. 产出落点
1. **只写 `docs/` 的 Markdown。**
2. `docs/` + 同步生成 `data/` 下 JSON。
3. `docs/` + 附带 `data/` 字段映射草案（不实际建文件）。

### C. 轮回机制
1. 前世记忆碎片 + 关键节点死亡回溯。
2. 纯记忆碎片（偏叙事，不做机制）。
3. **世代转世：灵魂跨越数百年多次转生。**
4. 时间循环：每次死亡回到起点。

## 决定

| 项 | 决定 | 备注 |
| --- | --- | --- |
| A 基调 | **纯东方仙侠** | 与 `src/data/types.ts` 的既有术语对齐，避免世界观和代码打架 |
| B 落点 | **只写 `docs/`** | 本轮不动 `data/`、`src/`；待 `data/schema/` 定稿后再由 `tools/` 脚本导出 |
| C 轮回 | **世代转世（多次转生）** | 灵魂跨越约四百年、转生七世，推动同一条「夙命线」 |

## 后果

### 直接收益
- 术语体系单一，法宝 / 符箓 / 御兽（召唤·捕捉）/ 灵宝 可直接映射到 `CommandId`，将来导出 JSON 无需语义转换。
- 「世代转世」天生适合 RPG 的**卷结构**：一世 = 一卷 = 一个时代 + 一个地理区 + 一批新人物，主线清晰、便于分期开发。
- 成长线可锚定《无职转生》式「低起点、长线、遗憾驱动」的写法。

### 需要承担的约束
- **放弃西幻**意味着不能出现「法师 / 咏唱 / 精灵 / 龙」等元素；魔法与武技的统一表述改为**术法（修真）与武技（武道）**。
- 主角跨越数百年、多世身份，**人物档案、配音、立绘的成本将成倍增长**。缓解手段：每世核心同伴控制在 2–3 人，跨世角色（苏昭、云鹤、殷无咎）复用。
- 第六世为主角转生为**女性**（凡人·柳眠）。这是服务「记忆与肉身身份同一性」主题的设计亮点，**但属于可调整项**：若后期判断对玩家理解造成干扰，可改为男性并保留同样剧情功能。此点单列，见下。

### Canon 铁律（后续写作不得违反）
1. 本界生灵死后经**忘川**洗忆，走「**常轮**」；主角是**外来灵魂**，不被忘川接纳，故保留记忆碎片，称「**畸轮**」。
2. 主角**无法选择转生对象**：出身、性别、天赋皆由「残余的执念 / 未了之因」牵引，本人仅能事后承接。
3. **长生与轮回互斥**：寿数越长的存在（殷无咎、云鹤、守碑人）越无法转世；主角每世必死、必转生。
4. 主角**记得的部分有限且会衰减错乱**（「残章」），因此「提前知道剧情」不能成为无代价的作弊，只能作为线索。
5. 结局的最终选择（**断轮 / 续轮 / 折中**）由玩家在第七世做出，前六世的选择仅改变难度、线索与结局文本，不改变"可选结局集合"本身。
