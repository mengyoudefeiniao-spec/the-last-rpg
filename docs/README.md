# docs/ —— 创作文档（唯一真相源）

人读的剧本与设计文档。子目录用「编号 + 中文名」，编号只为了让创作顺序在文件管理器里排得出来。

## 各目录职责

- `00-总览/`：一句话世界观、**术语表**、时间线。
  术语表是首要资产——所有人名、地名、技能、货币、组织先在这里登记再落笔，避免后续拼写与译名漂移。
- `10-世界/`：地理与阵营、历史与神话、规则体系（魔法/科技/经济/语言）。
- `20-人物/`：主角、同伴、反派与 NPC，一人一档；子目录按戏份分组。
- `30-剧情/`：主线、支线、对话脚本、结局与分支条件。
- `40-玩法设计/`：战斗系统、数值与成长、交互与 UI、经济循环。
- `50-美术与音频/`：美术风格指南、资源清单与命名规则。
- `90-决策记录/`：ADR，文件名 `YYYYMMDD-标题.md`，写清背景 / 备选项 / 决定 / 后果。

## 写作约定

1. **角色档**固定小标题，便于将来逐字段搬进 JSON：

   ```markdown
   ## 基本信息   （ID、年龄、身份、阵营）
   ## 外貌
   ## 性格
   ## 背景故事
   ## 目标与动机
   ## 关系       （用规格化 ID 引用，如 char.hero）
   ## 属性与技能
   ## 台词示例
   ```

2. **剧情段落**必须写清四件事：触发条件、参与人物、玩家选择项、结果（含对剧情 flag 的影响）。
   只写「发生了一段感人的对话」是无法实现的。
3. **引用他人**时写规格化 ID，不要只写名字；名字会改，ID 不会。
4. **只有定稿的内容才进 `data/`**。草稿留在 `docs/`，免得半成品污染游戏数据。

## 与 data/ 的对应关系

| docs | data | 说明 |
| --- | --- | --- |
| `20-人物/*.md` | `data/characters/<id>.json` | 属性、成长、技能、立绘与精灵路径 |
| `30-剧情/对话脚本/*.md` | `data/dialogues/<id>.json` | 对白节点、分支、条件与效果 |
| `30-剧情/主线|支线/*.md` | `data/quests/*.json`、`data/story/*.json` | 任务定义与章节推进 |
| `40-玩法设计/数值与成长.md` | `src/config/balance.ts` | 数值表 |
