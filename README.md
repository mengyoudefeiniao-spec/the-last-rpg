# The Last RPG

> 一句话简介：待补。

## 当前状态

**服务端权威的战斗原型**：5v5 实时行动条战斗 —— 3D 战场 + 阵法 + 地形分区 + 场景 + 剧情事件区。

- 服务端（Node + WebSocket）持有全部权威状态，客户端只负责渲染与输入
- **实时行动条（ATB）**：每个单位攒行动值，速度决定快慢；条满才能行动 ——
  而你在选技能时，别人的条照样在走
- **我方阵法**：战斗外的配置，决定站位与阵图（五种阵，各有自己的阵位与连线）
- **布阵阶段**：开战前预览阵法、地形与场景。站位由阵法决定
- **地形分区**：站位决定吃到什么增益/减益（冻伤 / 灼地 / 灵泉回血 / 浊气）
- **场景可切换**：环境（天光、雾气、光照、地面）与天气（飞雪、骤雨、风沙、灵雾）
- **剧情事件区**：战场上方留着一块不渲染的区域，已接通「渡劫天雷」演示
- 一套战斗规则同时服务浏览器与测试 —— 同一份代码，两端直接跑

剧本与数据层尚未开始填充。

### 运行

```powershell
npm install       # 首次
npm run dev       # 同时拉起前端(Vite)与战斗服(Node)，终端会打印两个地址
npm test          # 全部测试：战斗规则 + 服务端 WebSocket 集成
npm run typecheck
npm run build     # 类型检查 + 前端生产构建到 dist/
```

也可以分开起：`npm run dev:client`（前端）与 `npm run server`（战斗服，默认 `ws://127.0.0.1:8787`）。

## 架构：服务端权威

```
浏览器                                  战斗服 (Node)
  ui / render                            battle-session.ts
      ↑  snapshot（完整状态）                    ↕
      ↑  tick（行动条心跳，10Hz）             Battle（行动条）
      └─ state/battle-mirror.ts  ←────────→  party-config.ts（队伍配置，落盘）
      └─ intent：act / 换阵 / 开战 / 触发事件 ──→
```

下行有**两类**消息，别混用：`snapshot` 是完整状态（状态变了才发），
`tick` 只有行动值（高频，为的是让条看起来在走）。

客户端**不做任何战斗推导**：扣多少血、谁先到行动点、特技能不能放，
全由服务端算完推过来；连「指令按钮该不该置灰」都是快照里的 `commands` 字段说了算。

战斗逻辑本身不感知网络 —— 它只认识一个 `BattleDirector` 接口。服务端挂的是**事件记录器**
（把动作点记成一份可供客户端播放的剧本），测试则干脆不挂（所有 await 直接跳过）。
同一份 `Battle`，两个消费者。

`src/` 分三层，依赖单向 `server → shared ← client`。五条不许破的边界见 `src/README.md`。

## 行动条（实时 ATB）

参考仙剑 3：

- 每个单位有一个 **0..100 的行动值**，每秒按 `速度 × gaugeRate` 往上走
- **攒满才能行动**：我方停下等你下指令，敌方立刻由 AI 出手
- **你在选技能时，别人的条照样在走** —— 犹豫久了，敌人的条可能先满、抢先动手
- 行动完条归零，从头再攒

所以**速度决定一切**：谁先到行动点、一轮里能行动几次。
速度 38 的单位约 3.3 秒攒满，速度 14 的要 8.9 秒 —— 差一倍还多。

**推进与播放是解耦的**：客户端播演出的时候，行动条**照常走** ——
那种「画面在演、条还在涨」的压迫感正是实时行动条的意义所在。
服务端不等客户端确认，剧本发过去之后客户端自己排队播。

**「轮」而不是「回合」**：行动条没有固定回合，但状态持续与 DoT/HoT 总得有个结算粒度 ——
这里取「全员各行动一次」为一轮。

**时间由外部注入**（`advance(deltaMs)`）：服务端按 100ms 节拍调用，测试直接喂一大段。
逻辑里没有任何定时器，所以整场战斗能在几毫秒内跑完。

## 战斗阶段

```
deployment → battle → （victory / defeat / fled）
```

| 阶段 | 做什么 |
| --- | --- |
| `deployment` | 布阵：预览阵法、地形与场景。站位由阵法定死，此处不能改 |
| `battle` | 交战：行动条持续推进，条满者行动 |
| `victory` / `defeat` / `fled` | 终局 |

注意**没有「回合阶段」了** —— 谁正等着下指令，看单位自己的 `awaitingCommand`。

## 阵法

**只作用于我方**（敌方不设阵法，用战场自带的槽位）。阵法是**战斗外**的设定：
存在服务端的队伍配置里（`.runtime/party-config.json`），开战时读取，战斗中不能换。

五种阵，各有自己的阵位与阵图连线，按名字的字形摊在地面上：

| 阵法 | 形状 | 阵位 |
| --- | --- | --- |
| 锋矢阵 | 箭头直指敌阵 | 锋头 / 左翼 / 右翼 / 左尾 / 右尾 |
| 鹤翼阵 | 两翼向前包抄 | 中军 / 左翼根 / 左翼尖 / 右翼根 / 右翼尖 |
| 鱼鳞阵 | 前后两列错位 | 前列左中右 / 后列左右 |
| 长蛇阵 | 一字斜贯全场 | 蛇首 / 蛇颈 / 蛇腰 / 蛇身 / 蛇尾 |
| 方圆阵 | 四角护住中军 | 中军 / 前后左右四角 |

阵图会画在地上（阵位圆环 + 连线），**布阵阶段最显眼，开打之后淡下去**。

目前阵法只决定「站哪」，还没有数值加成 —— 将来要加的话，在 `Formation` 上补一个 `effects` 字段即可。

## 地形

战场定义在 `src/shared/data/battlefields.ts`。地面划分若干圆形分区，每个分区带一组状态；
单位站在圈内就获得这些状态，走出去自动移除（每轮开始同步一次）。

| 战场 | 分区 | 效果 |
| --- | --- | --- |
| 雪山·寒鸦岭 | 冰封溪谷 / 霜牙崖 | **冻伤**：速度 -25%，每轮结束损失 4% 最大生命 |
| 炎域·地火裂口 | 地火裂缝 / 熔岩口 | **灼地**：法抗 -20%，每轮结束损失 5% 最大生命 |
| 仙源之地·灵泉 | 灵泉 / 浊气洼地 | **仙源滋养**：法抗 +20%，每轮回复 6% 最大生命；**浊气**：攻击与法强 -20% |

冻伤减的是速度 —— 在行动条下，这等于「出手更晚、出手更少」，比单纯掉血更疼。

关键在**阵法与地形的配合**：分区只盖住部分位置，换个阵法，踩进危险区的人数就变了。
比如雪山战场上，锋矢阵有 2 人冻伤，方圆阵则是 3 人 —— 这就是「阵法不是摆设」的地方。

想加一个新地形，只改 `battlefields.ts`；判定逻辑集中在 `terrain.ts` 一处，别处一行都不用动。

## 场景：环境与天气

这两样**只影响观感**，不参与任何战斗规则（所以它们和「战场」是分开的两个概念）。

- **环境**（`data/environments.ts`）：天光与雾气颜色、光照方向与强度、地面与网格配色。
  现有苍茫暮野 / 寒山雪原 / 赤炎焦土 / 灵源幽谷。
- **天气**（同文件）：粒子效果。现有晴 / 飞雪 / 骤雨 / 风沙 / 灵雾。

服务端把**完整数据**下发，而不是只给 id 让客户端查表 —— 这样客户端手里那份永远是服务端认定的那份。

## 剧情事件区

`Battlefield.eventArea` 定义了战场正上方的一块区域（默认中心 `y=26`、半径 16）——
**它目前完全不渲染**，只是给剧情事件预留的降临锚点：海啸、地震、渡劫天雷都从这里下来。

链路已经打通：`StageEventDef`（`data/stage-events.ts`）→ 服务端 `Battle.triggerStageEvent()`
结算 → 客户端 `playStageEvent()` 演出。现在只有演示用的「渡劫天雷」（顶栏那个 ⚡ 按钮），
将来接剧情系统时，就是往事件表里加条目、由剧情来触发。

## 3D 战场与界面

战场在 `src/client/render/battle-stage.ts`：敌方 5 个单位在画面**左上**、我方 5 个在**右下**，
头顶挂 `CSS2DRenderer` 投影的血条（纯 DOM，样式复用 CSS）。地形分区画成半透明圆盘与边缘环。

**右上角是行动条**：每个单位一个图标，位置就是它的行动值 —— 我方青色在上、敌方红色在下，
起点在最左，行动点是右端那道金色亮线。条满的图标会亮起来，**那才是能操作的角色**。

服务端 10Hz 推一次行动值，客户端用 `displayGauge()` 按速度插值补平（**演出期间也照常插值**），
所以条看起来一直是连续走的。

**视角规则**：只有布阵与交战阶段能拖动旋转、滚轮缩放，演出期间一律锁定。
方位角与俯仰角都做了限位，防止转到敌我背后让「敌上我下」的构图失去意义。

**演出速度**在顶栏可调（慢 / 常规 / 快 / 极快）。**默认「快」（2 倍速）**。

## 四条轨道

| 轨道 | 目录 | 读者 | 内容 |
| --- | --- | --- | --- |
| 创作 | `docs/` | 人 | 世界背景、人物设定、剧情、玩法设计 |
| 数据 | `data/` | 程序 | 游戏运行时读取的 JSON（**尚未启用**，目前数据内联在 `src/shared/data/`） |
| 实现 | `src/` | 程序 | TypeScript 源码 |
| 素材 | `public/` | 程序 | 图片、音频、字体等静态资源 |

`docs/` 是**唯一真相源**（设定以文档为准），`data/` 是它的**可执行投影**。

## 目录导航

```
docs/     剧本与设计文档（世界/人物/剧情/玩法）
data/     游戏运行数据（JSON，按实体一分一档）—— 尚未启用
src/      源码：shared（前后端共用）/ server（权威状态）/ client（表现）
public/   静态资源（构建时原样拷贝）
tests/    战斗规则测试 + 服务端 WebSocket 集成测试
tools/    开发脚本（dev.mjs 同时拉起前后端）
```

详见 `docs/README.md`、`data/README.md`、`src/README.md`。

## 命名约定

- **目录名**：一律英文、小写、短横线（`kebab-case`），不含空格。
- **代码文件**：`kebab-case.ts`；类型/类名 `PascalCase`。
- **文档文件**：允许中文命名，方便阅读。
- **数据文件**：文件名即 ID，如 `char.hero.json`、`quest.escape-village.json`。
